# Анализ драйверов производительности

## Описание

Система автоматизированного анализа экспертных оценок драйверов производительности предприятия. Проект извлекает данные из Excel-файлов с оценками экспертов, проверяет соответствие между высокорейтинговыми драйверами и итоговыми выводами с помощью LLM, и формирует отчет о пропущенных драйверах.

## Общий пайплайн

```
Excel с оценками          Парсинг в JSON         Анализ LLM           Excel отчет
(driver_1.xlsx)    →    (parsed.json)    →   (проверка)    →   (результаты)
```

**Этапы:**
1. **Парсинг**: `parse_driver.py` извлекает структурированные данные из Excel (секции, вопросы, оценки экспертов, комментарии, выводы)
2. **Подготовка данных**: Фильтрация драйверов по порогу оценок (≥9.0 или ≥7.0)
3. **LLM-анализ**: OpenAI GPT проверяет присутствие каждого высокорейтингового драйвера в итоговых выводах
4. **Отчет**: Генерация Excel-файла с драйверами, которые не нашли отражения в выводах

## Модель данных driver_analysis_results.json

Файл содержит результаты LLM-анализа всех секций с агрегированными замечаниями.

### Структура файла:

```json
{
  "section_results": [...],
  "remarks": [...],
  "driver_summary_map": {...}
}
```

### Описание полей:

#### 1. `section_results` (массив)
Результаты анализа по каждой секции документа.

**Пример элемента:**
```json
{
  "section_title": "ПЕРСОНАЛ",
  "applied_threshold": 9.0,
  "driver_checks": [
    {
      "number": "11",
      "driver_name": "Каких компетенций не достает персоналу?",
      "average_score": 9.0,
      "found_in_summary": true,
      "evidence": "3) -11 Развитие компетенций..."
    }
  ],
  "remarks": [
    {
      "number": "4",
      "driver_name": "До какого уровня проведена декомпозиция целей?",
      "issue": "нет в выводах"
    }
  ],
  "summary_driver_map": {
    "Оптимизация ФОТ": "Расходы составляют 15,6 млн руб..."
  }
}
```

**Поля объекта секции:**

| Поле | Тип | Описание |
|------|-----|----------|
| `section_title` | string | Название секции (ПЕРСОНАЛ, СТРАТЕГИЧЕСКОЕ РАЗВИТИЕ, ПРОИЗВОДСТВО ПРОДУКЦИИ) |
| `applied_threshold` | number | Примененный порог оценки (9.0 или 7.0 при отсутствии драйверов ≥9.0) |
| `driver_checks` | array | Массив проверок каждого драйвера на соответствие выводам |
| `remarks` | array | Замечания о драйверах, отсутствующих в выводах (в рамках секции) |
| `summary_driver_map` | object | Словарь {название драйвера: текст вывода из summary} |

**Поля объекта `driver_checks`:**

| Поле | Тип | Описание |
|------|-----|----------|
| `number` | string | Номер драйвера (например "11", "4") |
| `driver_name` | string | Полное название драйвера-вопроса |
| `average_score` | number | Средняя оценка экспертов по этому драйверу |
| `found_in_summary` | boolean | Найден ли драйвер в итоговых выводах (true/false) |
| `evidence` | string | Цитата из summary или пояснение об отсутствии |

**Поля объекта `remarks`:**

| Поле | Тип | Описание |
|------|-----|----------|
| `number` | string | Номер драйвера |
| `driver_name` | string | Название драйвера |
| `issue` | string | Описание проблемы (обычно "нет в выводах") |

---

#### 2. `remarks` (массив)
Агрегированные замечания по всем секциям (с добавлением `section_title`).

**Пример:**
```json
[
  {
    "number": "4",
    "driver_name": "До какого уровня проведена декомпозиция стратегических целей?",
    "issue": "нет в выводах",
    "section_title": "СТРАТЕГИЧЕСКОЕ РАЗВИТИЕ"
  }
]
```

---

#### 3. `driver_summary_map` (объект)
Общая карта всех драйверов с итоговыми выводами из всех секций.

**Пример:**
```json
{
  "Оптимизация ФОТ и вакансий": "Расходы на оплату труда...",
  "Снижение текучести кадров": "Текучесть кадров среди рабочих...",
  "Развитие компетенций": "Эксперты выявили дефицит..."
}
```

**Ключ** – краткое название драйвера
**Значение** – развернутый вывод с рекомендациями и инструментами БП

## Принцип работы

### Парсер (parse_driver.py)
- Читает XLSX через ZIP-архив (OpenXML формат)
- Извлекает:
  - Метаинформацию документа
  - Секции (ПЕРСОНАЛ, СТРАТЕГИЧЕСКОЕ РАЗВИТИЕ, ПРОИЗВОДСТВО)
  - Вопросы-драйверы с номерами
  - Оценки экспертов по ролям (склад, продажи, снабжение, директор)
  - Итоговые выводы по секциям (summary)

### Анализатор (analiz.ipynb)
- **Подготовка данных**: Фильтрует драйверы с высокими оценками
- **LLM-проверка**: GPT сопоставляет номера/названия драйверов с текстом выводов
- **Детекция пропусков**: Выявляет драйверы без упоминания в выводах
- **Отчетность**: Формирует Excel с детализацией по каждому пропущенному драйверу
