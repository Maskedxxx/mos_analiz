# 7-я итерация: Приказ о создании ИЦ потока

Обновлено: 2026-01-30

## Обзор

LLM-аудит документа **"Приказ о создании информационного центра пилотного потока"** (1.3).

Поддерживает два варианта документа:
- **Бумажный** (paper) — 10 правил
- **Электронный** (electronic) — 11 правил (дополнительная проверка электронного формата)

## Документы

| Тип | Файл | Описание |
|-----|------|----------|
| Бумажный OK | `documents/prikaz_ic_potoka_ok.docx` | Бумажный вариант |
| Электронный OK | `documents/prikaz_ic_potoka_el_ok.docx` | Электронный вариант |
| Шаблон бумажный | `templates/prikaz_ic_potoka_template.docx` | Шаблон (paper) |
| Шаблон электронный | `templates/prikaz_ic_potoka_el_template.docx` | Шаблон (electronic) |

## Чанки документа

Парсер разбивает документ на 7 чанков по маркерам:

| Чанк | Содержимое |
|------|------------|
| `шапка` | Таблица реквизитов (организация, ПРИКАЗ, дата) |
| `преамбула` | От заголовка "О создании ИЦ пилотного потока..." до "ПРИКАЗЫВАЮ" |
| `текст_приказа` | Пункты 1-5 с распоряжениями + подписант |
| `приложение_1` | Форма инфоцентра потока + таблицы показателей |
| `приложение_2_регламент` | Регламент работы (разделы 1-4) |
| `лист_ознакомления` | Таблица подписей |
| `подписант` | Должность + ФИО подписанта |

### Маркеры разделения

```python
MARKERS = {
    "заголовок_приказа": "О создании информационного центра пилотного потока",
    "приказываю": "ПРИКАЗЫВАЮ",
    "приложение_1": "Приложение № 1",
    "приложение_2": "Приложение № 2",
    "регламент": "РЕГЛАМЕНТ",
    "приложение_1_к_регламенту": "Приложение № 1 к Регламенту",
    "лист_ознакомления": "ЛИСТ",
}
```

Парсер использует fuzzy matching (порог 0.80) для поиска маркеров.

## Правила проверки

### Бумажный вариант (10 правил)

| # | Правило | Тип | LLM | Scope |
|---|---------|-----|-----|-------|
| 1 | Проверка заголовка документа | `template` | да | преамбула |
| 2 | Проверка имени файла | `target_only` | нет | имя_файла |
| 3 | Сверка текста приказа с шаблоном | `template` | да | текст_приказа |
| 4 | Проверка слова ПРИКАЗ и номера | `target_only` | да | шапка |
| 5 | Проверка города и даты | `target_only` | да | шапка |
| 6 | Проверка юр.формы и наименования | `cross_check` | да | шапка + подписант |
| 7 | Проверка подписанта | `target_only` | да | подписант |
| 8 | Проверка ФИО ответственных лиц | `target_only` | да | текст_приказа + регламент |
| 9 | Проверка дат в п.3 и п.4 | `target_only` | да | текст_приказа |
| 10 | Проверка структуры приложений | `template` | да | приложения + лист |

### Электронный вариант (11 правил)

Все правила бумажного варианта + дополнительное правило:

| # | Правило | Тип | LLM | Scope |
|---|---------|-----|-----|-------|
| 11 | Проверка электронного формата | `target_only` | да | текст_приказа + регламент |

Правило #11 проверяет:
- Слово "электронного" в п.1 текста приказа
- Пункт 4.9 в регламенте (инфоцентр в электронном виде)
- Пункт 4.10 в регламенте (протокол по итогам совещания)

### Типы сравнения

- **target_only** — проверка только целевого документа
- **template** — сверка с шаблоном
- **cross_check** — сверка между чанками

## Использование

```bash
cd седьмая_итерация

# Бумажный вариант (автоопределение)
python start.py prikaz_ic_potoka_ok.docx

# Электронный вариант (автоопределение по имени файла)
python start.py prikaz_ic_potoka_el_ok.docx

# Явное указание варианта
python start.py prikaz_ic_potoka_ok.docx --variant paper
python start.py prikaz_ic_potoka_el_ok.docx --variant electronic

# С указанием шаблона
python start.py prikaz_ic_potoka_ok.docx --template prikaz_ic_potoka_template.docx

# Режим отладки (только промпты без вызова LLM)
python start.py prikaz_ic_potoka_ok.docx --print-prompts
```

### Автоопределение варианта

Скрипт автоматически определяет вариант по имени файла:
- Содержит "эл" или "_el" → electronic
- Иначе → paper

## Прямой вызов скрипта аудита

```bash
python scripts/run_prikaz_ic_potoka_audit.py \
  --target documents/prikaz_ic_potoka_ok.docx \
  --template templates/prikaz_ic_potoka_template.docx \
  --variant paper \
  --model gpt-4.1-mini

# Электронный вариант
python scripts/run_prikaz_ic_potoka_audit.py \
  --target documents/prikaz_ic_potoka_el_ok.docx \
  --template templates/prikaz_ic_potoka_el_template.docx \
  --variant electronic \
  --model gpt-4.1-mini
```

## Логирование сессии

Каждый запуск создаёт папку `logs_result/session_YYYYMMDD_HHMMSS/`:

| Файл | Описание |
|------|----------|
| `audit_result.xlsx` | Excel отчёт с нарушениями |
| `final_results.json` | JSON массив нарушений |
| `rules_summary.json` | Сводка: статус каждого правила |
| `pipeline.log` | Лог выполнения с таймстампами |
| `parsed_docs/*.json` | Распарсенные документы |
| `prompts/rule_XX_prompt.txt` | Промпты для LLM |
| `responses/rule_XX_response.txt` | Ответы LLM |
