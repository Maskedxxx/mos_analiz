# 5-я итерация: Приказ о создании ИЦ (электронный вид)

Обновлено: 2026-01-30

## Обзор

LLM-аудит документа **"Приказ о создании информационного центра предприятия"** в электронном виде (1.5).

Документ аналогичен 4-й итерации (бумажный вариант), но предназначен для электронного документооборота.

## Документы

| Тип | Файл | Описание |
|-----|------|----------|
| Целевой OK | `documents/prikaz_ic_el_ok.docx` | Корректный документ |
| Целевой ERRORS | `documents/prikaz_ic_el_errors.docx` | Документ с ошибками |
| Шаблон | `templates/prikaz_ic_el_template.docx` | Эталонный шаблон |

## Структура папки

```
пятая_итерация/
├── start.py                         # Точка входа (CLI)

├── documents/
│   ├── prikaz_ic_el_ok.docx         # Целевой документ (OK)

    └── session_YYYYMMDD_HHMMSS/     # Результаты сессии
```

## Чанки документа

Парсер разбивает документ на 6 чанков по маркерам:

| Чанк | Содержимое |
|------|------------|
| `шапка` | Реквизиты: наименование компании, ПРИКАЗ, дата, номер, город |
| `текст_приказа` | От "О создании информационного центра..." до "Приложение № 1" |
| `приложение_1_к_приказу` | Форма инфоцентра предприятия с таблицей показателей |
| `приложение_2_к_приказу` | Регламент организации инфоцентра (разделы 1-4, термины) |
| `приложение_1_к_регламенту` | Матрица ответственности за актуализацию данных |
| `лист_ознакомления` | Лист ознакомления с приказом |

## Правила проверки (9 шт.)

| # | Правило | Тип | LLM | Scope |
|---|---------|-----|-----|-------|
| 1 | Проверка имени файла | `target_only` | нет | имя_файла |
| 2 | Проверка обязательных реквизитов в шапке | `target_only` | да | шапка |
| 3 | Сверка текста приказа с шаблоном | `template` | да | текст_приказа |
| 4 | Проверка заполнения обязательных полей | `target_only` | да | текст_приказа |
| 5 | Проверка приложения 1 | `target_only` | да | приложение_1_к_приказу |
| 6 | Проверка полей регламента | `target_only` | да | приложение_2_к_приказу |
| 7 | Сверка наименования компании | `cross_check` | да | шапка + приложение_2 |
| 8 | Проверка структуры матрицы | `target_only` | да | приложение_1_к_регламенту |
| 9 | Проверка листа ознакомления | `target_only` | да | лист_ознакомления |

### Типы сравнения

- **target_only** — проверка только целевого документа (наличие/заполненность)
- **template** — сверка целевого документа с шаблоном
- **cross_check** — сверка сущностей между разными чанками

## Использование

```bash
cd пятая_итерация

# Проверка документа (шаблон по умолчанию)
python start.py prikaz_ic_el_ok.docx

# С указанием шаблона
python start.py prikaz_ic_el_errors.docx prikaz_ic_el_template.docx

# Прямой вызов скрипта аудита
python scripts/run_prikaz_ic_llm_audit.py \
  --target documents/prikaz_ic_el_ok.docx \
  --template templates/prikaz_ic_el_template.docx \
  --model gpt-4.1-mini

# Режим отладки (только промпты без вызова LLM)
python scripts/run_prikaz_ic_llm_audit.py \
  --target documents/prikaz_ic_el_ok.docx \
  --template templates/prikaz_ic_el_template.docx \
  --print-prompts
```

## Логирование сессии

Каждый запуск создаёт папку `logs_result/session_YYYYMMDD_HHMMSS/`:

| Файл | Описание |
|------|----------|
| `audit_result.xlsx` | Excel отчёт с нарушениями |
| `final_results.json` | JSON массив нарушений |
| `rules_summary.json` | Сводка: статус каждого правила |
| `pipeline.log` | Лог выполнения с таймстампами |
| `parsed_docs/*.json` | Распарсенные документы |
| `prompts/rule_XX_prompt.txt` | Промпты для LLM |
| `responses/rule_XX_response.txt` | Ответы LLM |

## Отличия от 4-й итерации

Документ структурно идентичен 4-й итерации (бумажный вариант), но:
- Предназначен для электронного документооборота
- Имя файла: `1.5 Приказ о создании ИЦ с прилож. наименование предприятия`
- Специфика заполнения может отличаться
