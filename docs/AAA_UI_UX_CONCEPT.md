# UI/UX Концепция: Система аудита документов

**Дата создания:** 2026-01-29
**Версия:** 1.0

---

## 1. Обзор системы

### 1.1 Назначение

Система автоматической проверки корпоративных документов на соответствие внутренним стандартам.
Пользователь загружает документ - система возвращает список нарушений.

### 1.2 Поддерживаемые типы документов

| # | Тип документа | Формат | Особенности |
|---|---------------|--------|-------------|
| 1 | Приказ о создании ИЦ | DOCX | 9 правил проверки |
| 2 | Приказ о создании ИЦ (электронный) | DOCX | Вариация правил |
| 3 | Приказ о проведении выхода + График | DOCX + XLSX | Cross-file проверка |
| 4 | Приказы/Положения ППУ | DOCX | Пакетная проверка |
| 5 | КПСЦ (Карта потока) | XLSX | 25 правил валидации |
| 6 | Драйверы производства | XLSX | LLM-анализ секций |

### 1.3 Принципы UX

```
+--------------------------------------------------+
|  МИНИМУМ ДЕЙСТВИЙ     МАКСИМУМ ПРОЗРАЧНОСТИ      |
|                                                  |
|  1. Загрузить файл    1. Понятный прогресс       |
|  2. Дождаться         2. Ясные результаты        |
|  3. Скачать отчёт     3. Возможность деталей     |
+--------------------------------------------------+
```

## 8. Технические заметки

### 8.1 WebSocket для прогресса

Сервер отправляет события:
- `parsing_started` - начало парсинга
- `parsing_done` - парсинг завершён
- `rule_started {index}` - начало проверки правила
- `rule_done {index, status}` - правило проверено
- `report_ready` - отчёт сформирован

### 8.2 API Endpoints

```
POST /upload
  -> загрузка файла, создание сессии

GET  /status/{session_id}
  -> текущий статус проверки

GET  /download/{session_id}/report
  -> скачать Excel-отчёт

GET  /download/{session_id}/json
  -> скачать JSON

WS   /ws/{session_id}
  -> WebSocket для real-time прогресса
```

## 10. Глоссарий

| Термин | Описание |
|--------|----------|
| Целевой документ | Документ, загруженный пользователем для проверки |
| Шаблон | Эталонный документ для сверки (вшит в систему) |
| Правило | Единица проверки (одна инструкция для LLM) |
| Чанк | Логический блок документа (шапка, текст приказа, приложение) |
| Cross-file | Проверка данных между разными файлами (DOCX <-> XLSX) |
| Cross-check | Проверка данных между разными частями одного документа |
