## 1) Карта верхнего уровня (куда смотреть)

### Драйверы (Excel)

- `service.py` — CLI-оркестратор пайплайна (Excel → JSON → LLM → отчет).
- `web_service.py` — FastAPI веб-сервис (загрузка файла, прогресс по WebSocket, скачивание результатов).
- `parser.py` — парсер XLSX в структурированный JSON (OpenXML/zip, без pandas).
- `analyzer.py` — подготовка контекста, вызов LLM по секциям, сбор замечаний, генерация Excel-отчета.
- `config.yaml` — пороги отбора, параметры модели, папка результатов.
- `templates/index.html` — UI для `web_service.py`.
- `requirements.txt` — зависимости для веб/CLI сервиса драйверов.

Сгенерированные артефакты (не исходники):
- `results/` — результат каждого запуска драйверов (папки-сессии).
- `uploads/` — временные загруженные файлы веб-сервиса.

### Word-аудит (приказы/положения/пакет)

- `вторая_итерация/multi_docs_driver_2/pac_4/config/parser_paths.json` — “источник путей”: какие документы парсить и где они лежат (абсолютные пути).
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_all_llm_audit.py` — основной оркестратор: запускает все проверки и складывает результаты в `results/runs/<pipeline_id>/`.
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_order_llm_audit_v2.py` — аудит приказа по правилам ТЗ (LLM вызывается **по одному правилу**).
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_reg_comp_llm_audit.py` — аудит положения/регламента (аналогичная логика).
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_package_llm_audit.py` — кросс-проверки между комплектами документов (2 правила).
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_*` — парсеры документов/ТЗ (python-docx) в структурированные “чанки”.

Сгенерированные артефакты:
- `вторая_итерация/multi_docs_driver_2/pac_4/results/` — результаты запусков (в т.ч. `results/runs/...`).

### КПСЦ (большой Excel)

- `третья_итерация/run_all_validations.py` — мастер-скрипт: запускает валидаторы параллельно и собирает `validation_report.xlsx`.
- `третья_итерация/validation_rules.json` — реестр правил (индекс, название, источники данных, критерии).
- `третья_итерация/validation_scripts/validate_*.py` — по одному валидатору на правило (каждый генерирует JSON PASS/FAIL).
- `третья_итерация/parser_scripts/parse_*.py` — парсеры Excel-листов/областей в JSON (вход для валидаторов).
- `третья_итерация/parser_outputs/` — распарсенные JSON (вход валидаторов).
- `третья_итерация/validation_outputs/` — результаты валидаторов (JSON).
- `третья_итерация/validation_logs/` — подробные логи (если запускать с `--verbose`).
- `третья_итерация/validation_report.xlsx` — итоговый сводный отчет.

## 2) Папки “данные/архив/черновики” (не основной код)

- `legacy/` — старые/переходные скрипты и результаты (в т.ч. ранний вариант драйверов и старый аудит документов).
- `diman/` — прототип/ноутбук для драйверов (аналог логики, но в Jupyter).
- `multi_docs_driver/` — набор примерных входных файлов (Excel и Word), без сервиса/кода.
- `Prezentacia/` — презентации.
- `notes/` — заметки/черновые материалы.
- `results/`, `uploads/` — генерируемые папки (см. выше).
- `whisper_vmeste.py` — отдельный экспериментальный скрипт (не входит в 3 основные подсистемы).

## 3) Минимальные точки входа (что запускать)

Все подсистемы ожидают `OPENAI_API_KEY` в окружении (или как указано в их локальной документации).

### Итерации 1-3 (оригинальные реализации)
```bash
# 1) Драйверы (CLI)
python service.py <input.xlsx>

# 2) Драйверы (Web)
python web_service.py  # → http://localhost:8000

# 3) Word-аудит
python вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_all_llm_audit.py --config ...

# 4) КПСЦ
python третья_итерация/run_all_validations.py
```

### Итерации 4-7 (LLM-аудит документов)
```bash
# 4) Приказ о создании ИЦ (бумажный)
cd четвёртая_итерация_prikaz_ic && python start.py

# 5) Приказ о создании ИЦ (электронный)
cd пятая_итерация && python start.py

# 6) Приказ о проведении выхода + График обхода
cd шестая_итерация && python start.py

# 7) Приказ о создании ИЦ потока (авто-определение варианта)
cd седьмая_итерация && python start.py
```
