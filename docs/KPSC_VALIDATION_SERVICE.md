# Сервис валидации КПСЦ (большой Excel) — карта кода и принцип работы

Обновлено: 2026-01-16

Задача сервиса: проверить Excel‑файл КПСЦ (Карта Потока Создания Ценности) по набору правил (25 правил) и собрать итоговый отчёт PASS/FAIL.

В этой реализации пайплайн двухфазный:
1) **Парсинг Excel → JSON** (отдельные парсеры по листам/областям).
2) **Валидация JSON → (LLM) → JSON результатов → Excel‑отчёт**.

---

## 1) Где живёт сервис в репозитории

Основная реализация находится здесь:

- `третья_итерация/`

Ключевые файлы/папки:
- `третья_итерация/README_VALIDATION.md` — локальная документация (структура, запуск, форматы).
- `третья_итерация/run_all_validations.py` — мастер‑скрипт (оркестратор): запускает валидаторы параллельно и собирает отчёт.
- `третья_итерация/validation_rules.json` — реестр правил (метаданные + описание каждого правила).
- `третья_итерация/validation_scripts/` — валидаторы (по одному скрипту на правило).
- `третья_итерация/parser_scripts/` — парсеры Excel → JSON (по листам/таблицам/диаграммам).
- `третья_итерация/parser_outputs/` — уже распарсенные JSON (вход для валидаторов).
- `третья_итерация/validation_outputs/` — JSON‑результаты валидаторов.
- `третья_итерация/validation_logs/` — детальные логи (если запускать с `--verbose`).
- `третья_итерация/validation_report.xlsx` — итоговый Excel‑отчёт.

Пример целевого файла (из meta правил):
- `третья_итерация/КПСЦ и Спагетти ТС_Предприятие.xlsx`

---

## 2) Главная точка входа (что запускать)

Мастер‑запуск всех проверок:
- `python третья_итерация/run_all_validations.py`

Запуск одного валидатора:
- `python третья_итерация/validation_scripts/validate_<rule>_*.py --parser-outputs ... --output ...`

---

## 3) Принцип работы (архитектура)

### 3.1 Фаза A: парсинг Excel → JSON

Парсинг вынесен в `третья_итерация/parser_scripts/parse_*.py`.

Каждый парсер:
- принимает `--input` (xlsx) и `--output` (json),
- читает конкретный лист/область/таблицу,
- сохраняет JSON в формате, который потом ожидают валидаторы.

Важно: `третья_итерация/run_all_validations.py` **не запускает парсеры** — он работает по уже готовым файлам из `parser_outputs/`.

### 3.2 Фаза B: валидация JSON → результаты → Excel

**Реестр правил**: `третья_итерация/validation_rules.json`
- `meta` описывает версию/целевой файл/количество правил.
- `rules[]` — каждое правило содержит:
  - `rule_index`, `rule_title`, `section`,
  - текст требования (`requirement_expert`, `technical_description`),
  - какие JSON нужны (`source_files`, `source_path`),
  - критерии проверки (`validation_criteria`).

**Валидатор** (любой `третья_итерация/validation_scripts/validate_*.py`) делает одно и то же:
1) Загружает своё правило из `validation_rules.json` (по `RULE_INDEX`).
2) Загружает нужные JSON из `parser_outputs/` (в соответствии с правилом/скриптом).
3) Извлекает “факты” (считает, сопоставляет, достаёт поля, формирует списки).
4) Строит prompt с текстом правила + фактическими данными.
5) Вызывает OpenAI (модель фиксирована в скриптах), требует строгий JSON‑ответ.
6) Пишет результат в `validation_outputs/*.json`:
   - `status`: PASS/FAIL/ERROR/TIMEOUT/MISSING,
   - `discrepancy`: текст проблемы (если FAIL/ERROR).

**Оркестратор** `третья_итерация/run_all_validations.py`:
- загружает список правил,
- находит соответствующий валидатор по паттерну имени файла `validate_<rule_index>_*.py`,
- запускает каждый валидатор как отдельный процесс (`subprocess.run`) с таймаутом 300 сек,
- параллелит запуск через `ThreadPoolExecutor` (по умолчанию 5),
- собирает результаты в `третья_итерация/validation_report.xlsx`.

---

## 4) Входы/выходы

### Входы
- Excel‑файл КПСЦ (пример: `третья_итерация/КПСЦ и Спагетти ТС_Предприятие.xlsx`).
- JSON‑парсинг этого файла: `третья_итерация/parser_outputs/*.json`.
- Правила: `третья_итерация/validation_rules.json`.

### Выходы
- `третья_итерация/validation_outputs/validate_<rule>.json` — результаты по правилам.
- `третья_итерация/validation_report.xlsx` — сводный отчёт по всем правилам.
- `третья_итерация/validation_logs/*.log` — подробные логи (при `--verbose`).

---

## 5) Окружение и зависимости

- Требуется `OPENAI_API_KEY` в окружении (мастер‑скрипт проверяет наличие).
- Python зависимости (фактически используются): `openai`, `pandas`, `openpyxl` (см. `третья_итерация/README_VALIDATION.md`).
