## 1. doc_1 — 2.2 Приказ о внедрении ПА

**doc_type:** `prikaz_pa_implementing`
**Формат:** DOCX
**Парсер:** OCR (HunyuanOCR → vLLM) — стандартный pipeline как prikaz_ic_el

### Структура документа

- Шапка: организация, ПРИКАЗ, дата, номер, город
- Заголовок: "О ведении производственного анализа"
- Преамбула + ПРИКАЗЫВАЮ (5 пунктов)
- П.1: Руководителю подразделения — организовать ведение ПА
- П.2: Утвердить формы документов (3 приложения)
- П.3: Ответственному за "Управление проектами и изменениями" — методологическая поддержка
- П.4: Довести приказ до ответственных лиц
- П.5: Контроль за собой
- Подписант: должность + ФИО
- Приложение 1: Лист производственного анализа (формы, таблицы)
- Приложение 2: Цепочка помощи (примеры)
- Приложение 3: Лист проблем

### Разбивка на чанки (5 шт.)

| Чанк | Страницы | Содержание |
|------|----------|------------|
| `шапка` | 1 | Реквизиты: организация, ПРИКАЗ, дата, номер, город |
| `текст_приказа` | 1 | Заголовок, преамбула, пункты 1-5, подпись |
| `prilozhenie_1_forma_pa` | 2-3 | Лист ПА с таблицами |
| `prilozhenie_2_cepochka` | 3-4 | Цепочка помощи |
| `prilozhenie_3_list_problem` | 4-5 | Лист проблем |

### Правила проверки (6 шт.)

| # | Правило | LLM | Scope | Примечание |
|---|---------|-----|-------|------------|
| 1 | Проверка имени файла | non-LLM | имя_файла | filename_keywords: ["2.2", "Приказ", "внедрении", "ПА"] |
| 2 | Номер приказа и дата | LLM | шапка | Полная дата ДД.ММ.ГГГГ + номер с № |
| 3 | Должность и ФИО подписанта | LLM | текст_приказа | В конце после п.5 |
| 4 | Ответственный за "Управление проектами и изменениями" | LLM | текст_приказа | П.3 обязателен |
| 5 | Сверка с документом 0.2 (опционально) | LLM | cross_check | Требует загрузки 2 документов — отложить |
| 6 | Наличие всех 3 приложений | LLM | приложения | Проверить заголовки каждого |

### Интеграция

- **Что создать:** config.json, rules.json, chunks_vision.json + template/template.docx
- **Папка:** `doc_configs/prikaz_pa_implementing/`
- **Non-LLM:** Регистрация в filename.py (`@register("prikaz_pa_implementing", 1)`)
- **Сложность:** Низкая. Структура 1:1 как prikaz_ic_el
- **Блокеры:** Нет. Правило 5 (cross-check) опционально, можно отложить

## 2. doc_2 — 0.2 Карточка проекта

**doc_type:** `kartochka_proekta_om`
**Формат:** XLSX (Excel!)
**Парсер:** Нужен НОВЫЙ XLSX-парсер через openpyxl (НЕ Vision, НЕ OCR)

### Структура документа (6 листов Excel)

| # | Лист | Назначение |
|---|------|------------|
| 1 | Карточка проекта (ШАБЛОН) | Шаблон — пустая форма |
| 2 | Карточка проекта (Образец) | Заполненный пример — это целевой лист |
| 3 | Формулы расчета показателей | Справочник формул |
| 4 | Методика расчета (ШАБЛОН) | Шаблон методики |
| 5 | Методика расчета (ОБРАЗЕЦ) | Заполненная методика |
| 6 | выпадающий список | Допустимые единицы измерения |

### Разделы целевого листа

1. **Шапка** (строки 1-11): организация, название проекта, "Утверждаю", ГД, подпись, дата
2. **Вовлеченные лица** (строки 12-18): клиенты, периметр, владелец, границы, руководитель, команда
3. **Обоснование** (строки 12-18 правая часть): ключевой риск, обоснование
4. **Цели и плановый эффект** (строки 19-38): таблица показателей (мин. 5 шт.)
5. **Ключевые события** (строки 19-38 правая часть): милестоуны с датами

### Разбивка на чанки (7 шт.)

| Чанк | Лист | Области ячеек | Содержание |
|------|------|---------------|------------|
| `shapka` | Образец | B2:B7 | Организация, проект, подпись, дата |
| `stakeholders` | Образец | B8:K19 | 6 полей: клиенты, периметр, владелец, границы, рук., команда |
| `justification` | Образец | K8:V18 | Ключевой риск + обоснование |
| `indicators_table` | Образец | B20:H59 | Таблица показателей |
| `milestones_table` | Образец | K20:T59 | Таблица ключевых событий |
| `metodika_indicators` | Методика (ОБРАЗЕЦ) | B6:V35 | Методика для каждого показателя |
| `dropdown_values` | выпадающий список | A1:D20 | Справочник единиц |

### Правила проверки (13 шт.)

| # | Правило | LLM | Примечание |
|---|---------|-----|------------|
| 1 | Имя файла | non-LLM | "0.2 Карточка проекта" |
| 2 | Юридическая форма и название | LLM | ООО/ЗАО/АО + название |
| 3 | Название потока | LLM | Обязательно в начале |
| 4 | Подписант + дата | LLM | Должность + ФИО + дата |
| 5 | Вовлеченные лица (6 полей) | LLM | Все 6 заполнены |
| 6 | Формат ФИО-должность | LLM | "ФИО - должность" в команде |
| 7 | Команда проекта (cross-check) | LLM | Сверка с Приказом об ответственных — отложить |
| 8 | Обоснование + ключевой риск | LLM | Оба поля заполнены |
| 9 | Последовательность дат | non-LLM | начало <= окончание для каждого события |
| 10 | Минимум 5 показателей | non-LLM | Подсчёт непустых строк |
| 11 | Единицы измерения vs справочник | non-LLM | ед.изм. из таблицы vs лист "выпадающий список" |
| 12 | Ед.изм. в методике = в карточке | LLM | cross_check между листами |
| 13 | Способ расчета и источник | LLM | Для каждого показателя заполнены |

### Интеграция

- **Что создать:**
  - `doc_configs/kartochka_proekta_om/config.json` + `rules.json`
  - `audit_engine/parsers/kartochka_proekta_om.py` — **НОВЫЙ парсер** (openpyxl)
  - `audit_engine/non_llm_checks/kartochka_proekta_om.py` — правила 1, 9, 10, 11
  - Регистрация парсера в `audit_engine/parsers/__init__.py`
- **НЕ нужен:** chunks_vision.json (данные извлекаются по координатам ячеек, без Vision)
- **Сложность:** Высокая
  - Нужен новый парсер с обработкой merged cells, формул, datetime
  - openpyxl `data_only=True` не вычисляет формулы — нужен кэш
  - Fallback логика: лист "Образец" vs "ШАБЛОН"
  - 4 non-LLM проверки с прямым доступом к ячейкам
- **Блокеры:**
  - Cross-check правила (7, 12) требуют внешних документов
  - Уточнить: откуда брать "Соглашение", "Протокол выбора потока", ССР

### Отличие от существующего kartochka_proekta (doc_type 2.4)

Существующий `kartochka_proekta` — это другой документ (2.4), уже есть в test_matrix.json.
Новый `kartochka_proekta_om` (0.2) — отдельный тип с другой структурой и правилами.

## 3. doc_3 — 0.5 Приказ о переходе на этап тиражирования

**doc_type:** `prikaz_tirazh`
**Формат:** DOCX
**Парсер:** OCR (HunyuanOCR → vLLM) — стандартный pipeline

### Структура документа

- Шапка: организация, ПРИКАЗ, дата, номер, город
- Текст приказа: преамбула, ПРИКАЗЫВАЮ (3+ пункта), подпись
- Приложение 1: Чек-лист/матрица тиражирования (таблица: критерий, ответственный, срок)
- Приложение 2: Регламент тиражирования (4 раздела: цель, ответственные, процедуры, контрольные точки)
- Лист ознакомления (последняя страница, опционально)

### Разбивка на чанки (5 шт.)

| Чанк | Страницы | Содержание |
|------|----------|------------|
| `шапка` | 1 | Реквизиты |
| `текст_приказа` | 1-2 | Преамбула, пункты, подпись |
| `приложение_1_к_приказу` | 2-3 | Чек-лист тиражирования |
| `приложение_2_к_приказу` | 4-6 | Регламент тиражирования |
| `лист_ознакомления` | -1 | Таблица подписей |

### Правила проверки (9 шт.)

| # | Правило | LLM | Scope | Примечание |
|---|---------|-----|-------|------------|
| 1 | Имя файла | non-LLM | имя_файла | "0.5 Приказ о переходе на этап Тиражирования" |
| 2 | Реквизиты в шапке | LLM | шапка | 5 элементов: ПРИКАЗ, дата, номер, город, организация |
| 3 | Сверка текста с шаблоном | LLM | текст_приказа (template) | Игнорировать плейсхолдеры, искать реальные ошибки |
| 4 | Обязательные поля в тексте | LLM | текст_приказа | Дата тиражирования, ответственный, подписант, ссылка на приложения |
| 5 | Приложение 1 (чек-лист) | LLM | приложение_1 | Номер/дата + заголовок + таблица с данными |
| 6 | Приложение 2 (регламент) | LLM | приложение_2 | 4 раздела: цель, ответственные, процедуры, контрольные точки |
| 7 | Наименование компании (cross) | LLM | шапка + приложения | Одинаковое во всех местах |
| 8 | Дата/номер в приложениях (cross) | LLM | текст + приложения | Совпадение с шапкой |
| 9 | Лист ознакомления | LLM | лист_ознакомления | Заголовок + дата/номер + таблица подписей |

### Интеграция

- **Что создать:** config.json, rules.json, chunks_vision.json + template/template.docx
- **Папка:** `doc_configs/prikaz_tirazh/`
- **Non-LLM:** Регистрация в filename.py (`@register("prikaz_tirazh", 1)`)
- **Может понадобиться:** `strip_annotations_chunks: ["текст_приказа"]` (как в prikaz_ic_el)
- **Сложность:** Низкая. Максимально похож на prikaz_ic_el
- **Блокеры:** Нет
