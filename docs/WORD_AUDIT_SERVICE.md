# Сервис проверки Word-документов (приказы/положения) — карта кода и принцип работы

Обновлено: 2026-01-16

Задача сервиса: автоматически сверять **целевые .docx** с **шаблонами** и требованиями **ТЗ** с помощью LLM и формировать отчёт по несоответствиям (JSON + Excel).

---

## 1) Где живёт “сервис Word-аудита” в этом репозитории

Основная реализация находится здесь:

- `вторая_итерация/multi_docs_driver_2/pac_4/`

Внутри:
- `вторая_итерация/multi_docs_driver_2/pac_4/config/parser_paths.json` — единый реестр входных документов: `id`, `parser`, `path` (пути сейчас абсолютные).
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/` — парсеры документов/ТЗ + раннеры LLM‑аудита.
- `вторая_итерация/multi_docs_driver_2/pac_4/docs/` — локальная документация + команды запуска.
- `вторая_итерация/multi_docs_driver_2/pac_4/archive25-11-13/` — архив исходных docx (версии/шаблоны/ТЗ).
- `вторая_итерация/multi_docs_driver_2/pac_4/results/` — результаты запусков (в т.ч. `results/runs/...`).
- `вторая_итерация/multi_docs_driver_2/pac_4/tests/` — тесты парсеров (юнит‑тесты).

## 3) Принцип работы (архитектура)

### Общий паттерн

1) **Конфиг путей** (`config/parser_paths.json`) определяет, какие `.docx` являются:
   - целевыми документами (version),
   - шаблонами (template),
   - ТЗ (tz).
2) **Парсинг**: документ превращается в структурированные “чанки” (шапка/тело/мета/разделы/таблицы).
3) **Разбор ТЗ**: ТЗ превращается в список правил (`index`, `title`, `content`).
4) **LLM-аудит “одно правило — один запрос”**:
   - для каждого правила строится отдельный prompt,
   - в prompt подаются ТОЛЬКО разрешённые блоки (SCOPE) и режим сравнения (COMPARE).
5) **Выход**:
   - stdout: JSON‑массив нарушений,
   - файл: Excel (`.xlsx`) с теми же нарушениями.

## 4) Ответственность модулей (кто за что отвечает)

### Оркестратор

- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_all_llm_audit.py`
  - создаёт `run_dir = results/runs/<pipeline_id>/`,
  - параллельно запускает 4 одиночных аудита (2 приказа + 2 положения),
  - затем запускает пакетную кросс‑проверку,
  - складывает `.xlsx` отчёты в папку запуска.

### Аудит приказов (order_*)

- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_order_llm_audit_v2.py`
  - читает `parser_paths.json` (id: target/template/tz),
  - парсит целевой приказ и шаблон в чанки: `чанк_шапка`, `чанк_текст`, `чанк_мета`,
  - парсит ТЗ в список правил,
  - формирует `RuleSpec` для каждого правила:
    - `compare`: `template` или `target_only`,
    - `scope`: какие части документа разрешены для правила (HEADER/BODY/META/...),
  - делает вызов LLM по каждому правилу (в параллельных потоках),
  - агрегирует нарушения и сохраняет в `.xlsx`.

Парсеры приказов/ТЗ:
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_order_comp_ppu_docs.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_order_comp_ppu_tz.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_order_ppu_docs.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_order_ppu_tz.py`

### Аудит положений/регламентов (reg_*)

- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_reg_comp_llm_audit.py`
  - работает для двух типов документов:
    - `reg_comp_ppu_*` (положение о конкурсах),
    - `reg_ppu_*` (положение о ППУ),
  - парсит целевой документ и шаблон в:
    - `чанк_шапка`,
    - `чанк_разделы` (список разделов с заголовками и текстом),
    - дополнительно для `reg_ppu` — `таблица_категорий`,
  - парсит ТЗ (формат может отличаться: `правила` vs `blocks`),
  - по каждому правилу строит prompt с блоками:
    - `TARGET_HEADER`, `TARGET_BODY`, `TARGET_SECTIONS`, `TARGET_CATEGORIES`, `TARGET_META`,
    - и (если `compare=template`) зеркальные `TEMPLATE_*`,
  - делает вызов LLM по каждому правилу и сохраняет нарушения в `.xlsx`.

Парсеры регламентов/ТЗ:
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_reg_comp_ppu_docs.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_reg_comp_ppu_tz.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_reg_ppu_docs.py`
- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/parser_reg_ppu_tz.py`

### Пакетная кросс‑проверка 4 документов

- `вторая_итерация/multi_docs_driver_2/pac_4/scripts/run_package_llm_audit.py`
  - грузит 4 документа из `parser_paths.json` и парсит их парсерами приказов/положений,
  - содержит 2 правила “в коде”:
    1) сверка номеров/дат в шапках приказов и соответствующих положений,
    2) сверка должности+ФИО: пункт 2 приказа ↔ пункт 3.1 положения,
  - по каждому правилу строит один prompt и вызывает LLM,
  - сохраняет результат в `.xlsx`.

## 5) Входы/выходы и форматы

### Входы

- `config/parser_paths.json` — какие документы проверяются.
- `.docx` файлы из `archive25-11-13/` (версии/шаблоны/ТЗ).

### Выходы

- `results/runs/<pipeline_id>/...xlsx` — отчёты по каждому прогону (если запускать `run_all_llm_audit.py`).
- stdout каждого скрипта — JSON‑массив нарушений (удобно для машинной обработки).

Формат “нарушения” (типовой):
```json
[
  {
    "rule_index": 1,
    "rule_title": "…",
    "Целевой документ": "…",
    "Различие": "…"
  }
]
```
