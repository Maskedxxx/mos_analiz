# Сервис LLM-аудита документа "Приказ о создании ИЦ" (4-я итерация)

Обновлено: 2026-01-28

Задача сервиса: автоматически проверять документ "Приказ о создании информационного центра предприятия" (.docx) по набору правил ТЗ с использованием LLM и формировать отчёт по несоответствиям (JSON + Excel).

---

## 1) Расположение в репозитории

Основная реализация:
- `четвёртая_итерация_prikaz_ic/`

Структура:
```
четвёртая_итерация_prikaz_ic/
├── start.py                    # Точка входа (CLI)
├── config/
│   └── tz_prikaz_ic.json       # Правила проверки (9 правил)
├── scripts/
│   ├── parser_prikaz_ic_docs.py    # Парсер документа → чанки
│   └── run_prikaz_ic_llm_audit.py  # Скрипт LLM-аудита
├── documents/                  # Целевые документы для проверки
│   ├── prikaz_ic_ok.docx       # Документ без ошибок
│   └── prikaz_ic_errors.docx   # Документ с ошибками
├── templates/
│   └── prikaz_ic_template.docx # Шаблон для сверки
└── logs_result/                # Результаты запусков
    └── session_YYYYMMDD_HHMMSS/
        ├── parsed_docs/        # Распарсенные документы (JSON)
        ├── prompts/            # Промпты для каждого правила
        ├── responses/          # Ответы LLM
        ├── pipeline.log        # Лог выполнения
        ├── rules_summary.json  # Сводка по правилам
        ├── final_results.json  # JSON с нарушениями
        └── audit_result.xlsx   # Excel-отчёт
```

## 2) Точка входа (запуск)

Простой запуск через `start.py`:
```bash
# Проверка документа (шаблон по умолчанию)
python start.py prikaz_ic_ok.docx

# Проверка с указанием шаблона
python start.py prikaz_ic_errors.docx prikaz_ic_template.docx
```

Прямой вызов скрипта аудита:
```bash
python scripts/run_prikaz_ic_llm_audit.py \
  --target documents/prikaz_ic_ok.docx \
  --template templates/prikaz_ic_template.docx \
  --model gpt-4.1-mini
```

Режим отладки (только промпты без вызова LLM):
```bash
python scripts/run_prikaz_ic_llm_audit.py \
  --target documents/prikaz_ic_ok.docx \
  --template templates/prikaz_ic_template.docx \
  --print-prompts
```

## 3) Архитектура

### Общий паттерн

1. **Парсинг** — документ разбивается на 6 чанков по маркерам.
2. **Загрузка правил** — из JSON-конфига загружаются 9 правил.
3. **Проверка** — для каждого правила:
   - non-LLM правила (index=1) — синхронно, без вызова API
   - LLM правила — параллельно через OpenAI API
4. **Агрегация** — результаты собираются в JSON и Excel.

### Компоненты

| Компонент | Файл | Назначение |
|-----------|------|------------|
| CLI-обёртка | `start.py` | Удобный запуск с поиском файлов |
| Парсер | `scripts/parser_prikaz_ic_docs.py` | Разбиение .docx на чанки |
| LLM-аудит | `scripts/run_prikaz_ic_llm_audit.py` | Оркестрация проверок |
| Правила | `config/tz_prikaz_ic.json` | Конфигурация правил проверки |

## 4) Парсер документа

### Чанки документа

Парсер разбивает документ "Приказ о создании ИЦ" на 6 чанков по маркерам:

| Чанк | Содержимое |
|------|------------|
| `шапка` | Реквизиты: наименование компании, слово "ПРИКАЗ", дата, номер, город |
| `текст_приказа` | От "О создании информационного центра..." до "Приложение № 1" |
| `приложение_1_к_приказу` | Форма инфоцентра предприятия с таблицей показателей |
| `приложение_2_к_приказу` | Регламент организации инфоцентра (разделы 1-4, термины) |
| `приложение_1_к_регламенту` | Матрица ответственности за актуализацию данных |
| `лист_ознакомления` | Лист ознакомления с приказом |

### Маркеры разделения

```python
MARKERS = {
    "заголовок_приказа": "О создании информационного центра предприятия",
    "приложение_1_к_приказу": "Приложение № 1",
    "приложение_2_к_приказу": "Приложение № 2",
    "приложение_1_к_регламенту": "Приложение № 1 к Регламенту",
    "лист_ознакомления": "ЛИСТ",
}
```

Парсер использует fuzzy matching (порог 0.80) для поиска маркеров.

### Пример распарсенного документа

```json
{
  "имя_файла": "prikaz_ic_ok.docx",
  "путь": "/path/to/document.docx",
  "шапка": "ООО «Ромашка»\nП Р И К А З\n27.08.2025 г. №15БП\nг. Москва",
  "текст_приказа": "О создании информационного центра...",
  "приложение_1_к_приказу": "Приложение № 1\nк приказу №15БП...",
  "приложение_2_к_приказу": "РЕГЛАМЕНТ\nорганизации информационного центра...",
  "приложение_1_к_регламенту": "Матрица ответственности...",
  "лист_ознакомления": "ЛИСТ ОЗНАКОМЛЕНИЯ С ПРИКАЗОМ..."
}
```

## 5) Правила проверки

### Структура правила

```json
{
  "index": 3,
  "title": "Сверка текста приказа с шаблоном",
  "scope": "текст_приказа",
  "compare": "template",
  "llm": true,
  "content": ["Инструкция 1", "Инструкция 2", ...]
}
```

### Типы проверок (compare)

| Тип | Описание |
|-----|----------|
| `target_only` | Проверка только целевого документа (наличие/заполненность) |
| `template` | Сверка целевого документа с шаблоном |
| `cross_check` | Сверка сущностей между разными чанками целевого документа |

### Список правил (9 штук)

| # | Тип | LLM | Scope | Проверка |
|---|-----|-----|-------|----------|
| 1 | target_only | нет | имя_файла | Имя файла соответствует шаблону |
| 2 | target_only | да | шапка | Обязательные реквизиты заполнены |
| 3 | template | да | текст_приказа | Текст совпадает с шаблоном |
| 4 | target_only | да | текст_приказа | Обязательные поля заполнены |
| 5 | target_only | да | приложение_1_к_приказу | Номер/дата приказа, обязательные элементы |
| 6 | target_only | да | приложение_2_к_приказу | Заполнены поля регламента (п.1.1.1, 2.1-2.8, 4.1-4.2) |
| 7 | cross_check | да | шапка + приложение_2 | Наименование компании совпадает везде |
| 8 | target_only | да | приложение_1_к_регламенту | Структура таблицы матрицы |
| 9 | target_only | да | лист_ознакомления | Дата и номер приказа присутствуют |

## 6) Построение промптов

### Системный промпт

LLM получает единый системный промпт с инструкциями:
- Роль строгого аудитора
- Формат ответа (JSON с status: ok/fail)
- Правила игнорирования плейсхолдеров (даты, ФИО, должности)

### Пользовательский промпт

Формируется динамически для каждого правила:

```
RULE_INDEX: 3
COMPARE: template
SCOPE: текст_приказа
RULE_TITLE: Сверка текста приказа с шаблоном
RULE_INSTRUCTIONS:
- Сверить текст в "текст_приказа" целевого с шаблоном
- Игнорировать: даты, ФИО, должности
...

CONTEXT:
[TARGET_текст_приказа]
О создании информационного центра...
[/TARGET_текст_приказа]

[TEMPLATE_текст_приказа]
О создании информационного центра...
[/TEMPLATE_текст_приказа]
```

## 7) Формат результатов

### JSON-ответ LLM

```json
{
  "status": "fail",
  "rule_index": 2,
  "rule_title": "Проверка обязательных реквизитов",
  "нарушения": [
    {
      "Целевой документ": "27.08.2025 г.",
      "Различие": "Дата должна быть без 'г.'"
    }
  ]
}
```

Или при отсутствии нарушений:
```json
{"status": "ok"}
```

### Итоговый JSON (final_results.json)

```json
[
  {
    "rule_index": 1,
    "rule_title": "Проверка имени файла документа.",
    "Целевой документ": "prikaz_ic_ok",
    "Различие": "Ожидалось: «1.5 Приказ о создании ИЦ с прилож»"
  }
]
```

### Excel-отчёт

Колонки: `rule_index`, `rule_title`, `Целевой документ`, `Различие`

## 8) Логирование

Все артефакты сессии сохраняются в `logs_result/session_YYYYMMDD_HHMMSS/`:

| Файл/папка | Содержимое |
|------------|------------|
| `parsed_docs/target_doc.json` | Распарсенный целевой документ |
| `parsed_docs/template_doc.json` | Распарсенный шаблон |
| `prompts/rule_XX_prompt.txt` | Промпт для правила XX |
| `responses/rule_XX_response.txt` | Ответ LLM для правила XX |
| `responses/rule_XX_non_llm.txt` | Результат non-LLM проверки |
| `pipeline.log` | Лог выполнения пайплайна |
| `rules_summary.json` | Список правил с метаданными |
| `final_results.json` | Итоговый JSON с нарушениями |
| `audit_result.xlsx` | Excel-отчёт |

## 9) Окружение и зависимости

- `OPENAI_API_KEY` — обязательно (или хардкод в `start.py`)
- Python-библиотеки: `openai`, `python-docx`, `pandas`, `openpyxl`
- Модель по умолчанию: `gpt-4.1-mini`
- Параллельность: 4 потока для LLM-проверок
