# Этап 2 — Отложенные проверки (cross_file)

Условия, требующие данных из внешних систем.
Когда появится `--external-data <path>` — дописать логику в соответствующие валидаторы.

## Правило 1: Название файла
- [ ] Загрузка ожидаемого имени файла из БД документов через API (сейчас захардкожен паттерн `"0.2 Карточка проекта"`)

## Правило 2: Вид организации и название
- [ ] Условие 2: сверка org_name с Соглашением (DOCX)

## Правило 3: Название потока
- [ ] Условие 2: сверка project_name с «Протокол выбора потока» (DOCX)

## Правило 4: Подписант
- [ ] Условие 2: сверка ФИО/должности с Соглашением (DOCX)
- [ ] Условие 3: дата подписания не позднее даты окончания мероприятия 1.4 из ССР (XLSX/API)

## Правило 5: Обязательные поля секции 1
- [ ] Условие 3: команда проекта совпадает с Приложением 1 Приказа об ответственных (DOCX)

## Правило 7: Даты мероприятий
- [ ] Условие 2: сверка дат с Битрикс (API)

## Правило 8: Показатели и даты
- [ ] Условие 2 (даты): сверка дат База/Цель/Идеал с событиями из секции 4
- [ ] Условие 2 (значения): сверка значений показателей с текущей/целевой/идеальной КПСЦ (XLSX)

## Правило 9: Единицы измерения
- [ ] Полный справочник единиц из DOCX (500+ единиц) вместо dropdown-листа

---

**Формат внешних данных (план):**
CLI-аргумент `--external-data external.json` с содержимым:
```json
{
  "soglashenie": {"org_name": "...", "signee_name": "...", "signee_position": "..."},
  "protocol_potoka": {"flow_name": "..."},
  "ssr": {"event_1_4_end_date": "2024-03-01"},
  "prikaz": {"team": ["ФИО1 - должность1", ...]},
  "bitrix": {"events": [{"name": "...", "start": "...", "end": "..."}]},
  "kpsc_current": {"indicators": [...]},
  "kpsc_target": {"indicators": [...]},
  "kpsc_ideal": {"indicators": [...]},
  "units_full": ["единица1", "единица2", ...]
}
```
