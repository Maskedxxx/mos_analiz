# Механики генерации документов (`mos_generated`)

## Принцип

Детерминированная подстановка в утверждённый шаблон Word, **без модели**: `.docx` с метками
`{{ключ}}`, рендер `docxtpl`. Постоянный методический текст живёт в шаблоне, меняются реквизиты.

## Контракт генератора (`generators/<тип>.py`, один класс на тип)

| Поле | Назначение |
|---|---|
| `DOC_TYPE` | идентификатор = имя шаблона = ключ реестра |
| `TITLE` | название в форме |
| `TEMPLATE` | путь к `templates/<тип>.docx` |
| `SCHEMA` | поля формы: `{key, label, type, required, source, hint?, default?}` |
| `defaults()` / `context(values)` | дефолты из схемы, поверх — непустые значения формы; склейки и падежи — здесь |
| `generate(values)` | проверка обязательных (после дефолтов) → `DocxTemplate.render` |

`SCHEMA` — единственный источник формы: интерфейс рисует поля и валидирует по ней. `source`:
`own` — вводит человек, `inherited` — если пусто, берётся из сессии (предыдущие документы).
Одинаковые `key` в разных типах (`org_full`, `signer_fio`) дают автозаполнение между типами.
Реестр — `registry.py::GENERATORS`; порядок и коды мероприятий (0.1 … 3.10) — `graph.json`.

## Единая точка входа

`engine.generate(doc_type, session_id, values, client)` — через неё оба HTTP-пути
(`POST …/generate` с JSON и `GET …/download` с query). Порядок:

```
генератор → inherited-поля из сессии → render → bytes → значения в сессию (in-memory)
          → стор по организации (файл) → трейс в журнал → отдать
```

Незаполненные обязательные → `ValueError` → HTTP 400 с перечнем ключей; неизвестный тип → 404.

## Автозаполнение по организации

Стор (`GEN_ORG_STORE`, по умолчанию `_org_store.json`): ключ — нормализованное название
(`normalize_org`: без юрформы из списка, кавычек, пунктуации, регистра; слово «Общество» не снимается),
значение — `поле → до 10 последних значений`, свежие первыми. `GET /api/orgs` — известные названия,
`GET /api/org/suggest?org=` — подсказки по полям. Заполняются только пустые поля.
Файл содержит ФИО реальных людей — в git нет.

## Скачивание

Только нативное: `GET /api/types/{тип}/download?<поля>` с `Content-Disposition: attachment`,
браузер сохраняет сам (во фронте — скрытый iframe). Сборка blob на клиенте не работает: файл
молча не сохраняется при «успехе» на экране.

## Журнал

`logs_generated/<тип>/session_<время>[_N]/` (`GEN_TRACES_DIR`): `meta.json` (время, тип, сессия,
клиент, статус, размер, ошибка), `values.json`, копия docx. Отказы — тоже, со `status: error`.
Запись под `try/except` — журнал не имеет права сорвать выдачу документа. Суффикс `_N` —
защита от двух генераций в одну миллисекунду.

## Правка шаблонов

`.docx` — zip. Точечные правки (заливка, выравнивание, метка) — распаковать, править
`word/document.xml`, с бэкапом исходника. Проверка меток:
`unzip -p templates/<тип>.docx word/document.xml | grep -o '{{[^}]*}}' | sort -u`.
Текст в текстбоксах (`w:txbxContent`) python-docx не видит — только через XML; там обычно две копии
(VML + DrawingML), править обе. Перегенерировать шаблон целиком нельзя — потеряется вёрстка заказчика.
