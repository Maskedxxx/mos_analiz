# Грабли (наступали, проверено)

## Сервисы и запуск
- **Правки не видны** — Python-бэкенды без `--reload`: после правки кода или базовых правил
  перезапускать (`scripts/restart_backend.sh`, `scripts/restart.sh`). Кастомные правила и шаблоны
  docx перечитываются на лету.
- **Без `.env` сервер проверки не стартует** — намеренно: нужны `AUDIT_LOGIN/PASSWORD/TOKEN`.
  Сообщение перечисляет незаданные переменные.
- **`set -e` в скриптах ожидания порта**: `[ … ] && break` и `code=$(curl …)` при отказе соединения
  роняют скрипт. В `scripts/` используются `if` и `|| true`; новые скрипты писать так же.
- **Docker на Mac**: порт `127.0.0.1:8081` может быть занят форвардом VS Code или локальным python —
  проверять стек через `:5174` (nginx) или изнутри сети compose.
- **`/api/health` отвечает 503 при `degraded`** (с 08.09): скрипты `restart_*` считают 503 «поднят, но внешний
  сервис недоступен», `healthcheck.sh` и Docker HEALTHCHECK — отказом. В health есть и `layout`.
- **«порт занят процессом PID»** от `restart_*.sh` — на порту чужой процесс (старый прод, забытый uvicorn);
  раньше скрипт печатал 200 чужого процесса и exit 0, а свой uvicorn умирал. Vite без `strictPort` при занятом
  порту молча уходит на соседний.
- **Ротация по объёму** (`LOGS_MAX_GB` 5, `UPLOADS_MAX_GB` 1, `GEN_TRACES_MAX_GB` 1; 0 — не чистить): при старте
  и раз в сутки удаляются самые старые сессии целиком. Загрузка после аудита переезжает из `uploads/<id>/`
  в `original/` сессии — `uploads/` живёт только во время аудита.

## Модель
- Режим рассуждений Qwen оборачивает JSON в markdown — всегда `enable_thinking: false`.
- Имя модели llama.cpp игнорирует: неправильное имя не даст ошибки, отвечает загруженная.
- «Каша» в ответе (меньше вердиктов, чем правил), пустой или не-JSON ответ — штатный повтор со сменой seed,
  до 5; после 5 — ошибка «Модель не вернула результат в ожидаемом формате». Правила без вердикта после
  всех попыток помечаются «НЕ ПРОВЕРЕНО» (`unchecked`), а не выдаются за пройденные.
- Документ больше `LLM_CONTEXT_TOKENS` (оценка 3 символа на токен) отклоняется до вызова модели —
  «Документ слишком большой для проверки»; llama.cpp иначе отдаёт сырой 400.
- Перед каждым вызовом модели уходит SSE-событие `llm_attempt` {layer, attempt, max} — UI показывает попытку.
- CLI: `--print-prompts` печатает промпты обоих слоёв и выходит без вызова модели; `--rule-filter` у
  generic-типа только предупреждает в stderr; ошибки парсеров — одна строка «Ошибка: …» и exit 2.
- Вердикты при temperature 0.7 могут отличаться на 1–2 между прогонами — это не регресс;
  регресс — иное число правил или структура отчёта.

## Типы и правила
- `parser_by_ext` и `engine` вместе или ни одного — `ValueError` при загрузке конфига.
- `engine` без строки в `src/engines.py` — тип не запустится нигде; `tests/test_registry.py` ловит.
- Правило «проверить, что значение верное» без формата/согласованности — модель придумает.
- Лист присутствия: раньше читались только 10 участников — лимиты строк в парсерах xlsx
  должны идти до первой пустой строки, не до константы.

## Документы
- Word разрывает метки `{{ключ}}` на несколько фрагментов — docxtpl их не увидит; проверять grep-ом по XML.
- Текстбоксы docx (`w:txbxContent`) невидимы для python-docx; данные в них дублируются (VML + DrawingML).
- Имена файлов с кириллицей через ssh в аргументах командной строки ломаются — передавать
  скриптом или архивом (tar/base64), в скриптах брать файлы по маске.
- macOS-архивы тащат `._*` файлы — чистить после распаковки на Linux.

## Браузер
- Chrome копит зависшую очередь загрузок и перестаёт сохранять файлы — лечится только полным
  выходом из Chrome; это не дефект приложения.
- Серверное SSE-событие ошибки называется `audit_error`, не `error`: имя `error` совпадает с DOM-событием
  обрыва EventSource — отсюда был дефект `"undefined" is not valid JSON` (закрыт 08.09, F24). При тишине
  60 с фронт сам спрашивает `/result`; сессия хранится в sessionStorage и восстанавливается после F5.
- Тексты ошибок изменились 08.09: «Тип документа не найден» (было «Неизвестный тип документа»); в генерации
  «Не заполнены обязательные поля» перечисляет подписи полей, не ключи — тесты ждут подписи.

## Данные
- В git не попадают: `tests/data/`, `test_docs/`, `_org_store.json`, `logs_*`, `uploads/`,
  `docs/методички/` — персональные данные и тяжёлые файлы. Проверять `git status` перед коммитом.
- В каталоге сессии с 08.09 есть `session.json` (итог для `/result` и `/download` после рестарта) и, при
  ошибке, `ERROR.txt` + traceback в `pipeline.log`; каталог есть и у ошибочных сессий.
- Битый `rules_custom.json` → 409 в API правил и предупреждение в аудите (базовые правила работают);
  рядом пишется `.bak` при каждом сохранении. Битый `_org_store.json` → переименовывается в `.broken-<время>`.
