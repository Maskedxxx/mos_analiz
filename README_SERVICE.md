# Сервис анализа драйверов производительности

Автоматизированный сервис для анализа экспертных оценок драйверов производительности предприятия с использованием LLM.

## Возможности

- ✅ **Веб-интерфейс**: Drag & Drop загрузка с real-time отслеживанием прогресса
- ✅ **Один вызов**: Excel → Excel (все промежуточные этапы выполняются автоматически)
- ✅ **Настраиваемые пороги**: Гибкая конфигурация порогов оценок через `config.yaml`
- ✅ **Система сессий**: Каждый запуск создает уникальную папку с результатами
- ✅ **Полная трассировка**: Сохраняются все промежуточные файлы (парсинг, LLM-анализ, отчет)
- ✅ **Безопасность**: API-ключ через переменные окружения
- ✅ **CLI + Web**: Используйте через командную строку или браузер

## Конфигурация (config.yaml)

### Структура файла

```yaml
# Настройки анализа драйверов
analysis:
  # Основной порог оценки для фильтрации драйверов
  primary_threshold: 9.0

  # Запасной порог, если драйверов с primary_threshold не найдено
  fallback_threshold: 7.0

# Настройки OpenAI API
openai:
  # API ключ (null = использовать OPENAI_API_KEY из окружения)
  api_key: null

  # Модель GPT для анализа
  model: "gpt-4o-mini"

  # Температура генерации (0 = детерминированный вывод)
  temperature: 0

# Настройки вывода
output:
  # Имя листа в итоговом Excel-отчете
  sheet_name: "Итог"

  # Папка для сохранения результатов
  results_dir: "results"
```

### Настройка порогов оценок

Пороги определяют, какие драйверы будут анализироваться LLM:

- **`primary_threshold`** (по умолчанию 9.0): Основной порог. Драйверы с оценкой ≥ этого значения попадают в анализ.
- **`fallback_threshold`** (по умолчанию 7.0): Запасной порог. Если драйверов с `primary_threshold` нет, используется этот порог.

**Примеры настройки:**

```yaml
# Строгий отбор (только оценки ≥ 9.5)
analysis:
  primary_threshold: 9.5
  fallback_threshold: 9.0

# Мягкий отбор (оценки ≥ 8.0)
analysis:
  primary_threshold: 8.0
  fallback_threshold: 7.0
```

### Выбор модели GPT

Поддерживаемые модели:

- `gpt-4o-mini` (по умолчанию, рекомендуется)
- `gpt-4o`
- `gpt-4-turbo`
- `gpt-3.5-turbo`

```yaml
openai:
  model: "gpt-4o"
```

└── 2025-10-08_143052_a7b3c4d5/

### Описание файлов

| Файл | Описание |
|------|----------|
| `00_input_*.xlsx` | Копия входного файла для архива |

| `03_report.xlsx` | Excel-отчет с пропущенными драйверами |

## Принцип работы

### Пайплайн обработки

```
1. Загрузка config.yaml
   ↓
2. Создание папки сессии: results/YYYY-MM-DD_HHMMSS_xxxxx/
   ↓
3. Копирование входного файла → 00_input_*.xlsx
   ↓
4. Парсинг Excel → 01_parsed.json
   ↓
5. Фильтрация драйверов по порогам (primary/fallback)
   ↓
6. LLM-анализ каждой секции → 02_llm_analysis.json
   ↓
7. Генерация Excel-отчета → 03_report.xlsx
   ↓
8. Вывод пути к папке сессии
```

### Логика порогов

1. Фильтруются драйверы с оценкой ≥ `primary_threshold`
2. Если драйверов нет, используется `fallback_threshold`
3. LLM проверяет наличие отобранных драйверов в выводах (summary)
4. Драйверы, отсутствующие в выводах, попадают в Excel-отчет

## Устранение проблем

### "OpenAI API key not found"

**Причина**: API-ключ не указан

**Решение**:

```bash
export OPENAI_API_KEY="sk-your-key"
```

Или укажите в `config.yaml`:

```yaml
openai:
  api_key: "sk-your-key"
```

### "Файл не найден"

**Причина**: Неверный путь к файлу

**Решение**: Проверьте путь или используйте абсолютный путь:

```bash
python service.py /full/path/to/driver_1.xlsx
```

### Ошибки LLM

**Причина**: Проблемы с OpenAI API

**Решение**:

1. Проверьте баланс аккаунта OpenAI
2. Проверьте правильность API-ключа
3. Попробуйте другую модель в `config.yaml`
